# SS003: NOT NULL added without validated evidence

Generated by `make docs` from the public registry; edit registry metadata to change this page.

Default base severity: **high**. Final risk also records known size/FK modifiers.

Historical rows may need checking; defaults do not prove nonnull rows.

## Required evidence

- Observed nullability changes or a newly added NOT NULL column are explicit.
- Historical nonnull proof requires the narrow retained, validated CHECK evidence.

## Conditional alternative

Add CHECK (column IS NOT NULL) NOT VALID under ACCESS EXCLUSIVE. It then checks new writes. Validate it under SHARE UPDATE EXCLUSIVE, which permits ordinary DML. SET NOT NULL still takes ACCESS EXCLUSIVE and may use the validated proof on PostgreSQL 13/15/16. Check inheritance/partition scope; this sequence is not lock-free.

## Boundaries and limitations

- A default does not prove historical values were backfilled or pre-existing NULLs removed.
- Registry severity is the rule default; condition-specific findings can use another base severity.
- Policy severity and confidence are distinct; unknown evidence is explicit.
- Confirmed operation effects require matching PostgreSQL 13/15/16 evidence.
- No calibrated duration or general safety guarantee is available.
